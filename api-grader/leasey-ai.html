The MCP step

An official MCP server moves the final grade up one step on the scale, once. It applies even past a gate's limit, and the score moves to the bottom of the new step's range.

C+ (77) → B- (80) B+ (88) → A- (90) A (94) → A+ (97)

The bottom line.

Leasey.AI earns a 95 (A), close to the 96 ceiling for a vendor without an official MCP server. A property manager can build their own tools on it to put units on rental marketplaces, bring in leads, and let an AI agent book and manage showings. The API comes with every plan, keys can be made read-only or limited to certain areas and revoked without calling support, and the docs are complete enough for an AI coding tool to work from directly. The limits: the published documentation shows no way to set showing availability, manage users, sign in through OAuth, or stop two systems from overwriting the same record, and no webhook fires when a showing changes. Getting a sandbox also means going through your Leasey contact.

What it is: Leasey.AI is an AI leasing platform that lists units, answers leads, schedules showings, screens applicants, and signs leases. It is a leasing front end, not a bank, PMS, or trust-accounting system, so you still need property management software (Leasey connects to Rent Manager, Buildium, DoorLoop, AppFolio, and Property Vista) as your system of record.

What works

  • API, webhooks, and sandbox included on every plan, with no usage cap
  • Create, update, and publish listings to marketplaces by API
  • Book, reschedule, confirm, or cancel showings, including from voice or chat agents
  • Pull and update leads, and move applicants through stages
  • Read-only and area-limited keys you create and revoke yourself
  • Clear error codes and a request ID on every response
  • Safe retries: an idempotency key works on every write
  • Full exports and incremental sync with updated_since
  • Signed, retried webhooks for listings, new leads, and application changes
  • Full guide, OpenAPI file, and llms-full.txt for AI coding tools

What to watch

  • The published documentation shows no way to set showing availability by API
  • The published documentation shows no team management beyond assigning members to units
  • The published documentation shows no endpoint for lead message threads
  • The published documentation shows no lockbox or access-code features
  • No documented webhook for showing changes, so you poll the showings report
  • Some older fields send numbers as text, and money is a plain decimal
  • The published documentation shows no guard against two systems overwriting edits
  • Sandbox access goes through your Leasey contact, not self-serve
  • The published documentation shows no OAuth sign-in, so apps need a pasted key
  • The terms let Leasey change the service without prior notice
