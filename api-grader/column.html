The MCP step

An official MCP server moves the final grade up one step on the scale, once. It applies even past a gate's limit, and the score moves to the bottom of the new step's range.

C+ (77) → B- (80) B+ (88) → A- (90) A (94) → A+ (97)

The bottom line.

Column is a real, nationally chartered bank (Column N.A., Member FDIC), so your money is held at Column itself rather than at a software company sitting on top of another bank. For an operator who wants to build, its API ranks among the most complete banking APIs available. Through it you can open accounts and per-property or per-owner account numbers, move money on every major U.S. payment rail, cancel or reverse payments, and pull statement and settlement data, all with tightly limited self-serve keys and a free sandbox. Retried payments do not double-send, webhooks are signed and retried, and an AI tool can read the full documentation in one file. The gaps come from what the published documentation leaves out, not from failures seen in testing: it shows no version or deprecation contract, no protection against two tools overwriting each other's edits, no OAuth sign-in for outside apps, and no official MCP server. Column markets property-management trust accounts and an AppFolio integration, but the API itself is general-purpose banking, so you still need a PMS or trust-accounting system for tenant and owner ledgers.

What it is: Column is a nationally chartered bank that gives developers API access to FDIC-insured accounts and payment rails, with a dedicated property-management page and an AppFolio integration. You still need a PMS or trust-accounting system for tenant and owner ledgers, and going live requires KYC/KYB checks.

What works

  • An actual bank (Column N.A., Member FDIC), not software on another bank
  • Separate account numbers for each property or owner, created through the API
  • Send money by ACH, wire, instant, book, check, and international wire
  • Cancel, return, or reverse payments on every major rail
  • Idempotency keys stop a retried payment from sending money twice
  • Signed webhooks, retried up to 25 times over 3 days
  • Statements and settlement reports in CSV, JSON, or Parquet for reconciliation
  • Read-only and narrowly scoped keys, with per-key approval rules
  • Free self-serve sandbox with separate test keys and isolated data
  • Public OpenAPI spec and llms-full.txt let AI tools learn the whole API

What to watch

  • No property-management trust-accounting endpoints, so your PMS still keeps the ledgers
  • The published documentation shows no protection against tools overwriting each other's edits
  • The published documentation shows no version pinning or deprecation policy
  • The published documentation shows no OAuth sign-in or official MCP server
  • Only Column's team can freeze an account; closing means deleting at $0
  • The published documentation shows no way to edit a saved payee
  • Rate-limit headers are not exposed, so you cannot see a limit coming
  • A missing record returns a 400 error instead of the documented 404
  • No published price list, so ask about account and payment fees
  • The changelog is product-level and lags the API reference

Gate 2 is scored against the published checklist for banking/payments software, fixed before the API was inspected and the same for every platform of that type. Critical items weigh 3, important items 2, and optional items 1. An item scores 1 when it is present with the operations it needs, 0.5 when it is partial, read-only where writes are expected, or only announced by an alert, and 0 when the published documentation shows no way to do it.
