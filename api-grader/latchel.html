The bottom line.

Latchel is a maintenance-coordination and AI call-center service that sits alongside your PMS. It is not a PMS, a bank, or a trust-accounting system, and your PMS stays the system of record. Its Partner API is a clean, self-serve REST API with an OpenAPI file, a "what changed since" sync, and webhooks, so you can build intake flows that create work orders, keep your property, resident, and vendor lists in sync, and feed job updates into your own reports or automations. The biggest limit is that the published documentation shows no API way to mark a work order complete, schedule it, or change its vendor; those steps stay in the Latchel app, or partly in Latchel's Claude and ChatGPT connector, which needs a person to sign in. Plan for one all-access key per company, no duplicate protection on creates, and a "next page" link that drops your page size, and handle those in your build.

What it is: Latchel is an AI maintenance-coordination and AI call-center platform for residential property managers, sold as software plus a service on a per-door subscription, not a PMS or a bank. You still need your PMS, which stays the system of record, and Latchel integrates with PMSs such as AppFolio, Rentvine, Buildium, Rent Manager, Propertyware, and Yardi.

What works

  • Any Latchel customer can generate an API key themselves, with no sales call
  • Nothing published says the API, webhooks, or MCP connector cost extra
  • Push work orders in from your own system, with your PMS ids attached
  • Keep properties, residents, owners, and vendors in sync through the API
  • Upload photos and files to a work order, including before and after shots
  • Approve or deny job budgets and cancel early-stage jobs through the API
  • Webhooks for jobs, residents, properties, invoices, files, and more
  • A documented "only what changed" sync, confirmed in live tests
  • Public OpenAPI file for the whole API, ready for AI coding tools
  • Official read-write MCP connector for Claude or ChatGPT, with sign-in instead of keys

What to watch

  • The published documentation shows no API way to mark a work order complete
  • The published documentation shows no API way to schedule or reschedule a job
  • A vendor can be set only at creation; reassigning happens in the dashboard
  • The published documentation shows no way to read or post work-order notes
  • One full-access key per company, with no read-only or scoped keys
  • Re-generating the key breaks every integration that uses it
  • No duplicate protection on creates, so a retry can make two work orders
  • The "next page" link drops your page size and can skip records
  • No overwrite protection, no request ID for support, and no public status page
  • Webhooks use a fixed shared secret, not a signature, with no documented retries
