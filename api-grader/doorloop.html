What this means for you.

One paragraph per category, in plain language.

1 · Functional Coverage

7.5 / 15 points

You can read nearly everything and do the day-to-day ledger work: create leases, move tenants in and out, post charges and payments, record bounced payments, and manage tasks, owners, vendors and bills. You cannot create properties or units, edit or renew an existing lease, read journal entries, reconcile, or handle rental applications through the API. Nothing pushes changes to you, so your tools have to poll on a schedule.

See technical details→

2 · Design & Reliability

5.5 / 10 points

The API is plain REST and easy to call. Rate limits are documented with a 429 and Retry-After, and a public status page publishes the API's uptime. Production automations still need defensive code: error formats vary, a retried request can create a duplicate payment or charge, updates overwrite the whole record with no conflict protection, there is no bulk export, and the published field names and types do not always match what the API returns.

See technical details→

3 · Access Control

5 / 5 points

With the newer OAuth (v2) path you can give an app or AI agent narrow, read-only or per-resource access and cut it off instantly. The catch is practical: v2 apps must be registered with DoorLoop and currently cover fewer endpoints, the everyday v1 key you create yourself can do whatever its user can do, and there is no sandbox, so every test touches live data.

See technical details→

4 · Docs & AI-Ready

3.1 / 5 points

AI coding tools can read DoorLoop's docs page by page in Markdown, which helps. But the downloadable spec link is broken, there are no SDKs, worked examples are sparse, and there is no API changelog. Expect to correct some field names and types by hand, and to find changes by testing rather than reading release notes.

See technical details→

5 · Access & Cost

15 / 15 points

On any current plan you can generate your own API key in settings today, with no sales call or upgrade. If you are on a legacy Starter or Pro plan, confirm that your plan includes the API.

See technical details→

Category 3 · Access Control

5 / 5
C3.1

Read-only credentials

.** v2 OAuth tokens carry only the approved <resource>:<action> scopes, and read means "List and get" (v2.0/reference/authentication §Scopes). Each endpoint declares its scope (for example, GET /leases requires leases:read in the v2 OpenAPI security). A *:read-only token is therefore read-only. Limitation: v2 apps must be registered by contacting DoorLoop (§1). v1 keys inherit the creating user's role, and no read-only v1 role is documented.

Yes

Scoped credentials

.** v2 offers fine-grained resource and action scopes (owners:read, tasks:create, tenants:update, …; v2 OpenAPI components.securitySchemes.OAuth2.flows.authorizationCode.scopes). v1 has role-based restriction only ("Each API token is assigned an access role…", reference/authentication, 405 callout).

Category 5 · Access & Cost

15 / 15
C5.1

Self-serve API key

.** A company user creates keys in Settings → Company → "Zapier & API Keys" after an SMS identity code and acceptance of the API Terms. There is no sales call or approval step (support article 6457764; reference/authentication). The operator for this run provisioned their own key, and it worked live. Note: the www.doorloop.com/partner page says DoorLoop is "selective about who gets access", and v2 OAuth apps must be registered by contacting DoorLoop. These describe partner and third-party app access, not an operator's own key (see disagreements).

Yes
C5.3

Not commercially gated

.** The base plan, "DoorLoop One", lists "Unlimited users, unlimited document storage and full API access", and the pricing FAQ states that "Everything that used to sit behind Premium, including… the API… is in DoorLoop One" (www.doorloop.com/pricing). The FAQ also says "Existing plans and prices stay as they are", so legacy Starter or Pro customers may still lack access, as the support article 6457764 Zapier note indicates.

Yes

What works

  • Create a full lease, move tenants in and out, and post charges, credits and payments
  • Record returned payments and manage tasks, work orders, owners, vendors and bills
  • Rent roll, P&L, balance sheet and cash-flow reports through the API
  • Documented rate limits with a 429 and Retry-After, and limit headers on every response
  • A public status page with a dedicated API component and published monthly uptime
  • Scoped, read-only OAuth tokens on v2, revocable instantly
  • Multiple named keys you create yourself in settings
  • Every reference page available as clean Markdown with its OpenAPI fragment
  • Full API access on the base DoorLoop One plan, with no sales call

What to watch

  • No webhooks, so every change has to be found by polling
  • No creating properties or units, and no editing or renewing an existing lease
  • No journal entries, reconciliation or rental applications through the API
  • No idempotency keys, so a retried payment or charge can post twice
  • Updates replace the whole record, with no conflict protection
  • Error formats vary and carry no stable machine-readable code
  • Some published field names and types do not match live responses
  • The published OpenAPI link returns a 404, and there is no SDK
  • No API changelog, and no versioning or deprecation policy
  • No sandbox, so every test touches live data
  • The everyday v1 key can do whatever its user can do; scoped access needs a DoorLoop-registered v2 app
  • Writes were graded from documentation, not tested live
